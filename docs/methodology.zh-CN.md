# 方法论

技能为什么这样工作。下面每条规则都堵住一种让回答偏离文档原文、过时或丢失事实的途径。具体流程写在技能里；[design-2.0.md](design-2.0.md) 和 [design-3.0.md](design-3.0.md)（英文）是设计及其实现步骤。[English](methodology.md)

## 要解决的问题

助手可以根据你的文档回答问题，但文档之间会互相矛盾：旧计划、较新的决定、又一次会议改了它。提问时再去搜索，得到的是最匹配的那份，而不是最新的那份；模型做总结时，还可能说出任何文档都没写的话。所以知识库在材料进来时就把对账做完，把结果存成普通文件，并把库里的每句陈述都绑定到它出自的那句原文。

## 证据链

每个回答都可以沿着链接一环一环追溯到某份文档里的一句话：

1. 来源：转换成 Markdown 的文档（由 doc2kb 转换），在 Sources/ 里一份一个文件，每段带锚点（`^p3`）。来源从不修改。
2. 卡片：从来源中取出的一条结论。包含模型用自己的话写的结论，以及它所依据的原句，链接到该段（`[[Sources/<来源>#^p3]]`），并带主题和实体。卡片放在 Cards/，每个来源一个文件。
3. 主题页：所有卡片关于一个主题的内容，新的在前，每句陈述都带引文和链接。主题页只由卡片生成，卡片变化时重建。
4. 状态卡：知识库的首页，记录现在成立的事实，一条一个编号，每条都引用其来源。

规范和它们放在一起，记录这个库自己的规则：分区与主题（表 A）、术语订正（表 B）、未决问题（表 C）、实体及别名（表 E）。

## 原则

- 无引文不成卡。只有脚本（quote_check.py）在所引段落里找到引文，卡片才会写入；比较时只忽略空白、全半角标点和强调标记，改写过的引文不能通过。被拒的卡片按来源重写一次，两次被拒就丢弃并列出。
- 脚本检查，模型提议。能机械检查的都由脚本检查，不靠模型判断：引文；模型写的主题页（check-page：引用的每一段都是该主题的现行卡片，每张这样的卡片都被引用）；状态卡改写（status-check：任何删除、改动或不再引用的来源，都要负责人看过）；回答里的引文（answer.py check）。
- 名称即版本。来源名称不带日期，同一文档的新版本以同一名称进来，替换旧版本。名称不同的版本作为候选找出（名称相近且有共同段落），确认后才替换。两份不同的文档不得同名。
- 只归档，不删除。被替换的来源及其卡片带时间戳移入 Archive/。旧版本中新版本不再包含的卡片会列出来，负责人可以恢复；恢复的卡片引用归档的来源，并注明来自较早版本。
- 改什么由负责人决定。新主题、新实体、版本对应关系和丢失的卡片，都连同本次入库的预览一起交给负责人，确认后才写入；不会悄悄扩张。引用了被替换来源的状态卡条目带上待复核标记（⏳），核实前不作为依据。
- 机械工作交给脚本。凡是能按规则决定的都由脚本完成，所以离线运行、能力一般的模型也够用：每批最多 2 万字符，一次读一个来源，主题页和回答材料由脚本组装，每个回答回复前都经过检查。模型只负责抽卡片和组织回复。
- 回答带引文。回答里每句事实陈述后面都跟着它所依据的原句和链接。阅读顺序固定（先状态卡，再主题页和卡片，最后来源），搜索次数有上限；库里没有记录的，就说没有记录。
- 没有代码就不写入。所有写入都经过脚本。没有代码环境（Python）时，技能仍可查阅和回答，但不向知识库写任何内容。

## 工作预设

一个起点，可在建库时调整：工作库的规范列出分区目标与计划、项目与事务、方案与成果、会议与决策、制度与流程、组织与分工、数据与报表、参考与模板，各带主题；状态卡开始时为空，按编号条目记录。表 B、C、E 起初为空，随负责人确认新的术语、问题和实体逐步增加；新主题追加到所属分区末尾，从不新增分区。
