# 知识库客户端：浏览器里的知识库

由本机提供、在浏览器中打开的页面，适合不用终端的人：安装技能、建库并告诉助手，备份、回滚、移动知识库、卸载，并直接和 OpenCode 对话：入库、随手记、提问。页面上列出已登记的知识库、哪些助手装了技能，以及 OpenCode 是否就绪。管理步骤的问题、预览和各项安全检查都来自 `install.py` 及其 `backup`、`rollback`、`move`、`uninstall` 子命令；对话与终端里的 OpenCode 共用同一套技能、注册表和 OpenCode 设置，两边可以同时使用。

[English](README.md)

## 文件

| 文件 | 说明 |
| --- | --- |
| `kb_client.py` | 本地服务：运行安装程序的各个步骤，把其中的问题转给页面 |
| `skills_admin.py` | 「技能」一栏：列出 OpenCode 读得到的技能，对知识库技能以外的技能做备份、回滚、导入和新建 |
| `agent.py` | 对话：在 127.0.0.1 上启动 `opencode serve`，管理页面上的各个窗口（每个窗口一个对话），把它们的事件转给页面，并代为回复客户端可以自行放行的授权请求 |
| `ingest_run.py` | 客户端自己的入库：按规则列出资料文件夹里的文档，运行 kb-ingest 的脚本，在客户端自己的窗口里请助手逐份写卡片，等你做决定，以及空闲时补抽卡片 |
| `auto.py` | 从知识库的投放文件夹自动入库 |
| `quick_search.py` | 快速搜索：把问题切成关键字，在各个本地知识库的索引里找出片段并排序，再直接调用一次 OpenCode 配置里的模型做归纳 |
| `web/` | 页面（`index.html`、`app.js`、`style.css`）；纯 HTML、JavaScript 和 CSS，不从网络加载任何内容 |
| `kb-client.desktop` | 双击入口，打开一个终端窗口运行 `kb_client.py`，并用默认浏览器打开页面。evergreen-wiki 最上层文件夹里也有同样的入口 |

## 运行要求

- Linux 桌面，Python 3.8 及以上（只用标准库），以及完整的 evergreen-wiki 文件夹：本工具调用上两级目录里的 `install.py` 和技能。
- 支持现代 JavaScript（`fetch`、`EventSource`）的浏览器，如较新的 Firefox 或 Chromium。
- 对话需要已配置好模型的 OpenCode（已在 OpenCode 1.19 上验证）。没有 OpenCode 时管理步骤照常可用，对话区会说明原因。OpenCode 配置文件里找不到模型时只给提示，因为配置可能来自别处；能不能用，以实际启动为准。
- 可选：`pdftotext`（poppler-utils）。没有时助手会整份读取 PDF，更慢也更费 token。

不需要联网。电脑不能联网时，从 [Releases](https://github.com/walkwithedi/evergreen-wiki/releases) 下载 evergreen-wiki-v<版本>.zip 拷过去解压，双击最上层文件夹里的 `kb-client.desktop`。

## 使用

1. 双击 evergreen-wiki 最上层文件夹或本文件夹里的 `kb-client.desktop`（知识库）。第一次双击时桌面可能询问是否信任或运行，选信任并启动。双击后只打开了文本时，在本文件夹打开终端，运行 `python3 kb_client.py`。页面会在默认浏览器中打开，终端窗口里显示页面地址。
2. 在左侧选择要做的事：
   - 安装与建库：选择助手（默认选中 OpenCode，页面上的对话用的就是它），安装三个技能，建一个知识库（文件夹、范围；写入前先给预览），并把知识库说明行写进助手的指令文件。选到已有知识库的文件夹时按原样登记。要再加一个库时再选一次。安装与建库完成后，客户端会重启它启动的 OpenCode，让对话马上用上新技能和说明行（助手正在处理时，等它处理完再重启）；对话接着进行。
   - 备份、回滚、卸载：同 `install.py backup`、`rollback`、`uninstall`（见 docs/manual-setup.zh-CN.md 第 6 节）。
   - 某个库下面的「关系图」：显示库里 Markdown 文件之间的链接，直接在页面上绘制，不从网络加载任何内容（`GET /api/graph`）。实体、汇总文件、文档、保存在库里的原件（原件文件夹）和尚未建页的链接各用一种颜色；客户端启动后新增或更新的文件加一圈高亮，勾选「只看本次新增或更新」时只留下这些文件和与它们相连的文件。滚轮缩放，拖动平移视图或移动单个文件，点击文件列出它链接到的和链接到它的文件。技能检索时跳过的内容这里同样跳过（归档文件夹、下划线开头的文件、快照和带时间戳的旧版），规范文件里的链接是规则示例，也不画。用 Obsidian 打开这个库文件夹，可以看到更完整的关系图和反向链接；页面上显示库路径，并有「复制路径」按钮。
   - 某个库下面的「入库」：由客户端自己把一个资料文件夹入库。选好文件夹后（须在家目录里或已挂载的磁盘上，即文件夹浏览器提供的位置；其他位置会被拒绝），页面按文件夹列出其中的文档，并标出现在抽卡的那些：勾选的文件夹（一个都不勾就是全部），填了日期的再加上修改日期不早于它的。所有文档都先入库，马上能检索和引用原文；其余的以后再抽卡。「开始入库」按 `ingest_run.py` 的步骤进行（`POST /api/ingest/plan`、`/api/ingest/start`）：转换、查重和比对版本、先入原文、抽卡（助手在客户端自己的窗口里每条消息只写一份来源的卡片，这些窗口不占 8 个对话窗口的名额；没通过核对的卡片带着原因退回一次；可以同时 1 到 4 路）、新主题和冲突、写入。与库里内容相同的文档不重复入库；同名文档成为一组，同名组、新主题、换了名字的新版本和冲突都在「等待确认」里等你决定。会替换库里某份文档的新版本，一定在这一轮里抽卡。进度列出每份文档的状态，有「停止」和「继续」（`/api/ingest/stop`、`/api/ingest/continue`；停止或因重启中断的入库从原处接着做），已停止或失败的入库还有「放弃」（`/api/ingest/discard`：删除它的工作文件夹，已经入库的内容保留），以及日志和汇总。入库在库内的 `.kb-work/client-<年月日-时分秒>/` 里进行（状态和日志都在这里）；入库完成后这个文件夹即被删除，日志另存为客户端日志文件夹里的 `ingest-<编号>.log`。运行期间写锁指向它的窗口。
   - 「入库」里的「空闲时补抽卡片」：在没有对话需要助手时（安静一分钟后），为先入原文、还没有卡片的文档补抽卡片，规则选中的优先，新的在前；任何窗口一发消息，它就停下这一轮让出助手。可以暂停、关闭，设置在下次启动时保留（`POST /api/backfill`）。卡片里有新主题的，在「等待确认」里等你决定，其余的直接写入。
   - 「入库」里的「自动入库」：放进知识库投放文件夹（中文库为 `_待入库`，英文库为 `_Drop`）的文档，两分钟不再变化、助手空闲时自动入库并抽卡；它的窗口里选择题按推荐项回答、授权自动放行，但需要你决定的事项照样等你。处理完的文档移到 `_已入库/<日期>`，读不出文字的移到 `_未处理`。有知识库打开自动入库时，关掉页面客户端也不会停止（`POST /api/auto`）。
   - 某个库下面的「体检」：客户端直接运行 kb-ingest 的只读体检（`ingest.py check`，`GET /api/check`），按类别列出发现的问题，每类一个可展开的列表：引文已不在所链接段落里的卡片、指向不存在文件的链接、缺少、过期或已不再生成的主题页、没有对应来源的卡片文件、状态卡中待复核或引用了非现行来源的条目、等待决定超过 7 天的入库、`.kb-work` 里超过 7 天未完成的入库；第一行给出来源总数和尚未抽卡的份数。不改动任何文件；主题页可以在对话里请助手重建。
   - 移动知识库，或点某个库下面的「移动」：选要移到哪个文件夹里，然后是 `install.py move` 的预览与确认。
3. 每一步输出的文字显示在它的问题上方。问文件夹时有「浏览…」按钮，打开文件夹浏览器：从家目录或已挂载的移动磁盘开始，逐级打开，选定一个文件夹。不推荐任何文件夹：浏览器从家目录打开。答案里已有的文件夹还不存在时（例如在预览里修改文件夹），浏览器从离它最近的已有上级文件夹打开，并把其余部分填为新建的文件夹名，直接选定即回答该文件夹；清空该名称则回答所选文件夹本身。建库预览用选项确认：「写入」「先修改某一项」（再选改哪一项）或「取消」；在终端里运行 `install.py` 时仍是输入同样的回答。
4. 步骤顺利完成后，面板收起为标题和结果一行（点「展开输出」可再看）；取消或出错的步骤保持展开。「安装与建库」补齐首次使用清单缺的项后，清单也自动收起一次；再手动展开就保持展开。
5. 「取消这一步」在当前问题处停止这一步，已完成的部分保留。「退出」停止客户端以及它启动的 OpenCode。关闭页面后，两者也会在一段时间后自动停止（`--idle`），助手仍在处理时除外。

### 首次使用清单

页面顶部的卡片列出对话需要的条件，缺哪项就写明怎么补：找到 OpenCode（装好后点「重新检测」，按启动时的方式重新查找）、OpenCode 已启动（停止或退回简易模式后点「重新检测」重新启动；配置里没有模型时在这一项给出提示）、三个知识库技能已装到 OpenCode 能读到的位置（它自己的技能文件夹、`~/.claude/skills` 或 `~/.agents/skills`；其他技能和其他助手不算）、已建好知识库、OpenCode 的指令文件里已写明知识库（它的 `AGENTS.md`；没有这个文件时是 `~/.claude/CLAUDE.md`）。后三项由「安装与建库」补齐。第六项可选，说明是否装了 `pdftotext`。前五项都完成后显示三个示例请求，点一下填进输入框，改好再发送。卡片可以收起，页面在浏览器里记住这个选择。还没有知识库时，对话区上方的任务按钮不可用。顶栏常驻一个标签，同样只看知识库技能（「已安装 3/3」或缺哪几个）；点开列出每个技能的位置、版本和检查过的文件夹，缺的时候有「去安装」。「安装与建库」「卸载」「回滚」完成后，技能列表会重新加载。

### 对话

客户端按下面的顺序查找 OpenCode：`--opencode <路径>`（或环境变量 `KB_CLIENT_OPENCODE`）、程序搜索路径、常见的安装目录（`~/.opencode/bin`、`~/.local/bin`、`~/bin`、`/usr/local/bin`、`~/.npm-global/bin`），最后是交互式 shell（`bash -ic`），这一步也能找到 `~/.bashrc` 里定义成函数或别名的 `opencode`；找到的是函数或别名时，之后都经 `bash -ic` 运行，函数里先做的事（比如刷新配置）照常进行。鼠标停在页面顶部的 OpenCode 标签上，可以看到找到的是什么、怎么找到的。

打开页面时，客户端在后台启动 OpenCode（`opencode serve`，只监听 127.0.0.1，在家目录运行），并显示它启动时输出的内容；启动可能要一段时间，客户端最多等 `--start-timeout` 秒。之后：

- 在底部输入框里提问或提要求；回车发送，Shift+回车换行。助手处理中也可以发送，消息先显示为「排队中」，等当前处理完再处理。「停止」结束助手当前的处理。
- 客户端自己的入库没做完时（进行中、等你决定、已停止或失败，包括因重启而停止的），从打开页面起就在对话区顶部显示一行：库名、已完成/总文档数、进度条和状态，按钮与入库面板相同（「停止」「继续」「放弃」），等你决定时有「查看」，「详情」打开入库面板。入库完成后这一行显示汇总，点「收起」隐藏。
- 助手回答里的来源链接（如 `[[Sources/…/名称#^p12]]`）显示为「名称 §12」，点开后在对话区上方显示该段及前后各两段（`GET /api/context`，取第一个包含该来源的本地知识库）。查询知识库直接在对话里提问：kb-query 通过库的索引找材料（中文、日文、韩文按相邻两个字匹配，按相关度排序）。
- 快速搜索：消息以「搜索」「搜一下」「查找」「查询」「查一下」「查查」「帮我查」「找一下」「介绍」「介绍一下」「讲讲」「讲解」「讲一下」「说说」「说一下」「解释」「解释一下」「什么是」「了解一下」「问一下」「有没有」「知识库里」（英文为 search、search for、look up、tell me about、what is）开头时，不发给助手，而是先在全部本地知识库里搜索（`POST /api/quick`）；输入框下方的「知识库搜索」开关打开后，这个窗口的每条消息都这样处理（开关按窗口各自记住，默认关闭，存在浏览器里）。去掉开头的词后，标点、空格和常见虚词把问题分成几段：中日韩文字不超过 4 个字的一段作为一个关键字，更长的切成相邻两个字，其他文字按词；单个字只在没有别的关键字时使用。命中关键字多的排在前面，同样多时状态卡条目、卡片、原文段落依次在前，再按相关度；不到最好一条一半关键字的不列出，最多 15 条（状态卡条目最多 5 条）。片段立即列出（折叠在「依据片段」里，点「原文」看该段前后），随后客户端直接调用一次 OpenCode 配置里的模型（当前窗口选的模型，没选时用默认模型；服务商的 baseURL、apiKey 和 headers，apiKey 可写成 `{env:变量}` 或 `{file:路径}`），按 OpenAI 兼容的 `/chat/completions` 流式归纳：只用这些片段，每句末尾标 [编号]，点编号展开对应片段；片段里没有的编号标出来。归纳不进对话，不占对话窗口，助手忙时也能用；不逐字核对引文，需要核对时点「深度搜索」，在当前窗口发出「用 kb-query 在知识库里查：原话」。一条都没找到时不调用模型。没能归纳（找不到配置或模型、没有接口地址或 AK、接口报错或超时）时只列片段并说明原因，不自动改发给助手。「交给助手」把原话照常发给助手，用于不是查知识库的消息。结果只留在页面上：切换窗口后还在，刷新页面后消失。
- 助手的每条回答下方有「复制回答」：复制回答本身的文字（不含折叠的过程说明和工具步骤），转成纯文本：`[[Sources/…/名称#^p12]]` 这样的来源链接写成（名称 §12），去掉 Markdown 标记，表格每行用制表符分隔。助手的回答占满对话区宽度；宽屏下展开知识库时，对话区也有约一屏高。
- 对话区上方的「随手记」把一句话立即记进知识库（kb-note）。入库在对话里提出，写明文件或文件夹路径（「入库：……」），其余由 kb-ingest 完成。
- 「等待确认」在有事项等你决定时出现在对话区上方。同名文档组列出各个成员：选哪一份是现行版，勾选「不是同一份」的会作为另一份文件保存。一组超过一行时有批量按钮（全部新增、全部并入某个主题、全选、全部接受或全部恢复），超过 8 行时还有筛选框；库里已有、不再入库的文档也列在这里。客户端自己的入库和补抽，在决定保存后会自己接着做，不在对话里另说。本地知识库入库写入前需要决定的事项（新主题、新实体、可能的新版本、冲突），kb-ingest 会写到库里的 `_pending/<轮次>.json`（`ingest.py pending write`；下划线开头，检索和关系图都会跳过）。页面把每一轮显示成表单：新主题选「新增」或「并入」规范里的某个主题，新实体选「新增」并选类型，或作为表 E 中某个实体的别名，版本候选勾选「是新版本」，冲突选「接受改动」或「恢复旧卡片」。「保存决定」先校验（`GET`、`POST /api/pending`），把决定写成同目录的 `_pending/<轮次>.decisions.json`，并在当前对话窗口里说一句决定已保存，助手据此接着完成这一轮（`ingest.py pending read`；归档完成后这两个文件会删除）。直接在对话里回答同样有效。表单下方列出状态卡中带 ⏳ 的待复核条目，每条有「问一下」，把问题填进对话框，由 kb-query 回到来源作答并提议更新。
- 日志：客户端写入 `~/.config/evergreen-wiki/logs/kb-client-YYYYMMDD.log`（INFO 级别，--log-level 设得更低时按它；保留 7 天，只有本人可读），记录 OpenCode 的启动、重启和停止，每个授权请求和处理结果（只记类型和路径，截断到 200 字符），每一步的开始和结束，以及客户端退出的原因。日志里有文件名和路径，没有文件正文。「管理」区显示日志位置，并有「复制路径」。
- 助手提出带选项的问题时，显示为选项卡片；助手用文字要求确认时，在输入框里回复。
- 「新对话」在当前窗口开始一个干净的对话；以前的对话仍保存在 OpenCode 里，可以在那里打开。
- 窗口：对话区上方一排标签，每个标签是一个窗口，各有自己的对话、卡片和「全部允许」开关，都由同一个 OpenCode 处理。「＋」新开一个窗口（最多 8 个），「×」关闭窗口，对话仍保存在 OpenCode 里；关闭助手正在处理或有卡片在等的窗口时先确认，确认后先停止再关闭；关掉最后一个窗口时留下一个新窗口。后台窗口的标签上用圆点标出处理中（蓝）或有卡片等你（黄），有新回复时标签加粗。普通窗口用 OpenCode 给对话起的标题，还没有标题时显示「对话 1」「对话 2」。「停止」「新对话」「在终端打开」「全部允许」只作用于当前窗口。窗口列表和当前标签存在 kb-client.json 里，刷新页面或重启客户端后照原样恢复。
- 管理步骤持有写锁：「安装与建库」「升级」「回滚」「移动」「卸载」会改知识库或技能，运行期间对话区上方有一行提示（点「查看」跳到步骤面板）；这时对话里的助手要改知识库里的文件、运行 kb-ingest 或 kb-note 的脚本、执行提到知识库文件夹的命令，一律弹卡片由你决定，即使开着「全部允许」；读知识库、kb-query 的检索脚本和只读命令照常自动放行。简易模式下只有一个窗口，没有标签栏。
- 一个回合结束后，每条回答里的步骤合并成一行（「12 个步骤（读取 5 · 运行命令 6 · 修改文件 1）」，有失败的标红并写明几个），点开可看每一步；回答文字照常显示，子助手的工作同样折叠，重开页面时已完成的回合也是折叠的。对话区高度随窗口变化。
- 助手的处理过程实时显示：每个步骤一行（读取文件、运行脚本等）；思考过程和步骤前的过程说明各折叠成一行灰色小字，点开看全文；正式回复按正常文字显示。交给子助手（OpenCode 自带的助手，如 explore）的工作缩进显示在「子助手」下面，包括子助手自己的步骤、授权请求和提问。
- 入库时，对话区上方显示阶段条：转换、核对引文、写入、主题页。当前阶段按正在运行的技能脚本确定（不看助手的措辞），并用一句话说明这一步为什么这样做；点开某个阶段可看详细说明。下面一行提示入库运行时间较长、页面可以留着不管，并给出在自己的终端里进入工作文件夹打开 OpenCode 的命令和「复制」按钮。客户端自动允许的操作合并成一行计数（「已自动允许 N 次」），点开看明细，不再每次一行。
- 思路轮播：欢迎区一次一张卡片，介绍知识库背后的思路（LLM Wiki、常青笔记、名称即版本、状态卡、有证据才改、改写有核对、只归档不删除、规范随材料生长、先查库再回答），每张一句话，点「详情」再看几句。约 8 秒换一张，鼠标或键盘焦点停在上面时暂停，有上一张、下一张和暂停；系统设了减少动态效果时不自动换。入库时阶段条下方显示一行精简版，点一下换下一张。
- 「技能」一栏在左侧，列出 OpenCode 读得到的全部技能（先是它自己的文件夹，再是 ~/.claude/skills 和 ~/.agents/skills；同名的以前者为准，后者标为未生效），显示版本、描述和触发口令。「试一试」把第一个口令填进对话框，不会自动发送。三个知识库技能排在前面，除「试一试」外只有「升级」：先备份，再用这个客户端带的版本替换 OpenCode 正在用的那份技能文件夹，不问装到哪里、是否替换。已登记的知识库文件夹还在时，知识库不变，只刷新说明行（有变化时问一次）；没有可用的库时，接着问是否建库。已安装的版本相同或更新时，或有步骤正在写知识库时，按钮置灰，悬停提示说明原因。其他技能有「修改」：卡片里选要改的方面（什么时候用、做什么、例子、回答、其他），写一两句说明，并附写好请求的要点；点「备份并准备请求」后，先把技能文件夹复制到 `~/.config/evergreen-wiki/skill-backups/<技能>/<时间>/`，再把请求填进对话框。有备份后出现「回滚」，先备份当前版本，再把选中的备份放回去。「导入」接受含 SKILL.md 的文件夹或 zip：先预览名称、描述、文件和大小，同名、zip 里有指向自身以外的路径或链接、超过 500 个文件或 20 MB 的一律拒绝，绝不覆盖；导入时不运行其中任何内容，复制到 OpenCode 的技能文件夹。「新建技能」问名称和一句用途，写一个待补全的 SKILL.md，并把补全它的请求填进对话框。
- 标题右边的「知识库」按钮用来展开或收起知识库：知识库列表、管理、「技能」一栏、步骤面板、阶段条和首次使用清单里与知识库有关的几项。收起时页面占满窗口，对话左边是只读的技能列表：每个生效的技能一行（名称和描述的第一句；点开看完整描述和触发口令），知识库技能在前，列表在栏内滚动，超过 8 个时出现筛选框。浏览器会记住是否收起；有步骤在运行时自动展开。宽屏上，左栏右上角的「«」把整个左栏收拢成一条窄栏，对话区随之变宽（页面最宽仍为 1440 像素）；窄栏上竖排写着「技能」（知识库展开时为「知识库」），点窄栏任何地方都会展开。浏览器记住是否收拢，用不用 `--chat-first` 分开记住，默认展开；点「知识库」按钮展开知识库时，左栏也一并展开。窄屏上左栏排在对话下面，不提供收拢。页面默认展开，用 `--chat-first` 启动时默认收起。
- 助手的回答按 Markdown 显示：标题、列表、引用、表格、分隔线、行内代码、加粗、斜体和网页链接。代码块用等宽字体，带「复制」按钮，Python、shell、JavaScript、JSON、YAML、SQL 和 diff 有语法着色，其他语言不着色。回答以页面元素构造，从不当作 HTML 插入，其中的内容不会被执行。自己发的消息仍按纯文本显示。
- 「在终端里打开」在新的终端窗口里用 OpenCode 自己的界面打开同一个对话（`opencode --session=<编号>`；终端程序依次尝试 x-terminal-emulator、mate-terminal、gnome-terminal、konsole、xterm），使用用户自己的 OpenCode 设置。在终端里继续时，页面上的这个对话会暂停，回来后刷新页面即可。

授权。客户端启动的这个 OpenCode，所有操作都先设为询问（通过 `OPENCODE_CONFIG_CONTENT`，只作用于这个进程，不改用户的 OpenCode 设置）。以下几类由客户端自动回复「允许这一次」：读写已登记的本地知识库里的文件；读取本次对话选中的材料、已安装的技能和助手自己的设置；派出只负责查找的子助手（explore）；运行已安装技能的脚本（`python3 <技能>/scripts/<名称>.py …`，前面最多一个 `cd <文件夹> &&`，引号内的参数之外不能有其他命令行语法；双引号内含 `$`、反引号或反斜杠时仍需确认）；以及在上述范围内的普通 `mkdir [-p]` 和 `cp [-p|-r|-R]`（cp 可从其中任一处读取，只能写到允许写入的地方），不能带通配符和 `~`；还有只读的命令（ls、cat、head、tail、wc、stat、file、du、grep、rg、不带 -exec、-delete 等动作参数的 find、pwd、echo、test），之间可用 `;`、`&&`、`||`、`|` 连接，最多带 `2>/dev/null`，只用 HOME、USER、KB_LIBRARIES、PWD 这几个变量，且每个路径都在上述范围内。消息里写出完整路径的文件和文件夹，算作本次对话选中的材料（只读）。客户端还在系统临时目录里建一个自己的工作文件夹，退出时删除；写这里和写知识库一样自动放行。子助手的请求按同样的规则处理。每次自动允许都会在对话里记一行。其余操作显示为卡片，写明助手要读、改或运行什么，按钮为「拒绝」和「允许这一次」。OpenCode 给出了以后不再询问的范围时（例如所有 `git` 命令），卡片上列出这个范围，并多一个「总是允许」：客户端把这个回答转给 OpenCode，之后这类操作不再询问，与在终端里一样。客户端也把这个回答记在自己的状态文件（kb-client.json）里，之后同类请求由客户端直接放行，OpenCode 或客户端重新启动后仍然有效；记住的命令范围只适用于单条命令，用 `;`、`|` 等连接的不算。「管理」区显示已记住几项，并有「清除」按钮：清除后客户端忘掉这些回答，并重新启动 OpenCode 让它也忘掉。不改用户的 OpenCode 设置文件。路径按真实路径比较，经符号链接跳出知识库的不放行。

全部允许。对话区标题栏的「全部允许」（每张卡片上也有「本页都允许」）按窗口各自开关：确认一次后，客户端对这个窗口里的请求自动回复「允许这一次」，包括已在等待的卡片，直到再点同一按钮关闭或退出客户端；其他窗口不受影响。管理步骤运行期间，写知识库的请求仍弹卡片（见上文「管理步骤持有写锁」）。刷新页面和「新对话」后都有效；只存在内存里，不写 kb-client.json，也不影响「总是允许」记下的回答。每次自动允许照常计入对话里的计数。对话里的选择题仍等你回答。简易模式下不可用。

简易模式。OpenCode 的服务没有按时启动，或缺少客户端用到的接口时，对话改为每条消息运行一次 `opencode run <消息>`，并在页面上说明；这种模式下助手不能在页面上请求授权或提问。在「首次使用清单」里点「重新检测」可以再试一次启动服务。

输入的不是绝对路径时，按家目录下的相对路径处理。

选项：`--lang en|zh` 指定语言（默认按系统语言），`--port N` 指定端口（默认自动选空闲端口），`--no-browser` 不打开浏览器、只显示地址，`--idle 秒数`（没有页面打开且没有步骤在运行达到这么久后停止；0 表示不自动停止；默认 120），`--start-timeout 秒数`（等待 OpenCode 启动的时间；默认 90），`--opencode 路径`（指定要用的 OpenCode 程序），`--log-level`。「安装与建库」还可用 `--agent <目标>` 预先回答选哪个助手（新库的档位随助手而定：OpenCode 为弱档，其他为强档），用 `--descriptions <文件>` 替换技能描述，与 `install.py` 相同；可以写一个包装脚本或复制一份 .desktop 入口，为一组使用者固定这些选项。`--simple` 去掉回滚、移动、卸载、「技能」一栏（只读的技能列表保留）和清除已记住授权的按钮，客户端也拒绝这些请求（403）；安装与建库、备份、关系图和对话（包括「全部允许」）照常可用。`--chat-first` 打开时以对话为主，相当于 OpenCode 的浏览器前端：知识库默认收起（见上文「知识库」按钮；浏览器与不带 `--chat-first` 的页面分开记住）。对话上方有工作文件夹、模型列表和「历史会话」。工作文件夹用文件夹浏览器选择（最近 5 个可以直接再选；不能是家目录本身、包含家目录的文件夹或系统文件夹）；OpenCode 在这个文件夹里启动，每个文件夹记住各自的一组窗口（切换文件夹要所有窗口都空闲、没有步骤在运行），助手在文件夹里读、改文件不再弹卡片；命令（只读命令除外）和文件夹以外的操作仍会询问。模型列表列出 OpenCode 配置里的模型，选择只对当前对话有效，开新对话后恢复默认。「历史会话」按时间倒序列出这个文件夹里的主对话，已在某个窗口打开的标「（已打开）」；点一个就在新窗口里接着聊，已经开着的就切到那个窗口。编辑步骤下有「查看改动」，显示这次编辑的差异（最多 400 行）。客户端不备份助手改动的文件：工作文件夹请选用有版本管理或有备份的文件夹。

## 安全

- 服务只监听 127.0.0.1。打开的地址带一个随机令牌；不带令牌或主机名不对的请求一律拒绝，浏览器里的其他网页无法调用本服务。
- 快速搜索由本服务直接请求 OpenCode 配置里的模型接口，请求里只有问题和检索出的片段；AK 只在本服务里使用，不发给页面，也不写进日志。
- 页面只和本服务通信，由本服务和 OpenCode 通信。OpenCode 自己的服务不设密码，本机任何程序只要找到它的端口就能调用，这与在终端里启动 OpenCode 相同。它只监听 127.0.0.1，端口在启动时随机选定，随客户端一起停止。
- 客户端在 `~/.config/evergreen-wiki/kb-client.json` 保存各窗口的对话编号和标题，在 `~/.config/evergreen-wiki/skill-backups/` 保存技能备份。只有「导入」「新建技能」「回滚」在确认后才写技能文件夹，从不写知识库技能的文件夹。
- 同一时间只运行一个步骤。文件夹浏览器只列出文件夹和文件名，且只能浏览家目录和已挂载的移动磁盘之内（其他位置的文件夹仍可直接输入到答案里）；服务只发送页面自己的三个文件；客户端本身不写任何东西，写入的只有安装程序各步骤在确认后写的内容。

## 在桌面上检查

单元测试按页面的方式通过 HTTP 回答问题。改动后请在真实桌面上检查：

1. 双击任一入口（最上层文件夹、tools/kb-client）能打开终端窗口，并在默认浏览器中打开页面。
2. 安装与建库：文件夹浏览器从家目录打开（在预览里修改文件夹时，从当前答案或其最近的已有上级打开，并填好新文件夹名），能看到已挂载的移动磁盘，选定后的路径出现在问题里；确认前能看清预览。
3. 移动：移动后页面上该库显示新位置，重启助手后能在新位置查到库里的内容。
4. 卸载：知识库文件夹默认保留，逐个选定并输入确认词后才删除。
5. 「取消这一步」停止当前步骤且不再改动任何东西；「退出」停止客户端，终端窗口随之关闭。
6. 对话：OpenCode 能启动，页面显示「已就绪」（记下用了多久）；问一个知识库里有的问题，能按库作答。
7. 入库：在消息里写明两个文件夹并要求入库；不用终端就能一直做到入库报告，阶段条随步骤变化。读取材料、写知识库不弹授权卡片；做这两者以外的操作时弹出卡片。
8. 重开页面后还是同样的几个窗口和对话；「新对话」在当前窗口开始一个干净的对话。开两个窗口，一个处理中时另一个能正常对话。
9. 点「退出」后，没有残留的 `opencode serve` 进程（`ps -ef | grep "opencode serve"`）。
10. OpenCode 只在终端里配置好（写在 `~/.bashrc` 里）时，双击启动也能找到它；页面顶部标签能看到是怎么找到的。
11. 子助手工作时，它的步骤缩进显示；派 explore 时不弹授权卡片。
12. 思考过程和过程说明折叠显示；助手处理中发出的消息显示为排队中。
13. 「在终端里打开」能在终端窗口里打开同一个对话。
14. 「安装与建库」默认选中 OpenCode，预览里不再有档位一项；完成后不用重启任何东西，就能直接问新库里的内容；重开客户端后，技能和知识库仍正常列出。
15. 在卡片上选「总是允许」后，同类操作不再弹卡片；记下退出并重开客户端后是否仍记住。
16. 入库 10 个文件：除确认预览外，没有关于工作文件夹或 mkdir、cp 的卡片。
17. 关系图：能从库卡片打开；本次入库的文件带高亮圈；用「复制路径」复制的文件夹能在 Obsidian 里打开。
18. 首次使用清单：在还没有技能和知识库的电脑上，卡片列出缺少的项，用「安装与建库」逐项补齐；装好 OpenCode 后点「重新检测」，不用重启客户端就能开始对话；「安装与建库」的预览用「写入」「先修改某一项」「取消」三个选项确认。
19. 少弹卡片：「安装与建库」完成后步骤面板和首次使用清单自动收起；用 ls、head、grep 查看库或材料里的文件不弹卡片；消息里写的路径读取时不弹卡片；退出并重开客户端后「总是允许」仍然记得，「管理」区的「清除」能让它忘掉；已完成的回合步骤合并为一行。
20. 思路轮播：卡片会自动切换，鼠标停在上面时暂停；桌面设了减少动态效果时，不点「下一张」就不换。浅色和深色主题下字体与颜色都清楚易读。
21. 技能：「试一试」只填对话框不发送；「修改」先备份再填请求；助手改完后「回滚」能恢复原版。kb-query 只有「试一试」和「升级」，刚做完「安装与建库」时「升级」是灰的；版本较旧时，有知识库的情况下「升级」不提任何问题，有步骤在运行时「升级」是灰的；用 ls 列它的文件夹不弹卡片。
