# 知识库客户端：浏览器里的知识库

由本机提供、在浏览器中打开的页面，适合不用终端的人：安装技能、建库并告诉助手，备份、回滚、移动知识库、卸载，并直接和 OpenCode 对话：入库、随手记、体检、提问。页面上列出已登记的知识库、哪些助手装了技能，以及 OpenCode 是否就绪。管理步骤的问题、预览和各项安全检查都来自 `install.py` 及其 `backup`、`rollback`、`move`、`uninstall` 子命令；对话与终端里的 OpenCode 共用同一套技能、注册表和 OpenCode 设置，两边可以同时使用。

[English](README.md)

## 文件

| 文件 | 说明 |
| --- | --- |
| `kb_client.py` | 本地服务：运行安装程序的各个步骤，把其中的问题转给页面 |
| `skills_admin.py` | 「技能」一栏：列出 OpenCode 读得到的技能，对知识库技能以外的技能做备份、回滚、导入和新建 |
| `intake.py` | 由客户端执行的入库：每个文件运行技能自己的脚本，只在修正术语和放置时询问助手，写进知识库后接着分轮整合 |
| `auto.py` | 自动入库：监视开了自动入库的知识库的投放文件夹，无人值守地启动 `intake.py` 的入库，并把处理完的文件移出投放文件夹 |
| `agent.py` | 对话：在 127.0.0.1 上启动 `opencode serve`，管理页面上的各个窗口（每个窗口一个对话），把它们的事件转给页面，并代为回复客户端可以自行放行的授权请求 |
| `web/` | 页面（`index.html`、`app.js`、`style.css`）；纯 HTML、JavaScript 和 CSS，不从网络加载任何内容 |
| `kb-client.desktop` | 双击入口，打开一个终端窗口运行 `kb_client.py`，并用默认浏览器打开页面。evergreen-wiki 最上层文件夹里也有同样的入口 |

## 运行要求

- Linux 桌面，Python 3.8 及以上（只用标准库），以及完整的 evergreen-wiki 文件夹：本工具调用上两级目录里的 `install.py` 和技能。
- 支持现代 JavaScript（`fetch`、`EventSource`）的浏览器，如较新的 Firefox 或 Chromium。
- 对话需要已配置好模型的 OpenCode（已在 OpenCode 1.19 上验证）。没有 OpenCode 时管理步骤照常可用，对话区会说明原因。OpenCode 配置文件里找不到模型时只给提示，因为配置可能来自别处；能不能用，以实际启动为准。
- 可选：`pdftotext`（poppler-utils）。没有时助手会整份读取 PDF，更慢也更费 token。

不需要联网。电脑不能联网时，从 [Releases](https://github.com/walkwithedi/evergreen-wiki/releases) 下载 evergreen-wiki-v<版本>.zip 拷过去解压，双击最上层文件夹里的 `kb-client.desktop`。

## 使用

1. 双击 evergreen-wiki 最上层文件夹或本文件夹里的 `kb-client.desktop`（知识库）。第一次双击时桌面可能询问是否信任或运行，选信任并启动。双击后只打开了文本时，在本文件夹打开终端，运行 `python3 kb_client.py`。页面会在默认浏览器中打开，终端窗口里显示页面地址。
2. 在左侧选择要做的事：
   - 安装与建库：选择助手（默认选中 OpenCode，页面上的对话用的就是它），安装三个技能，建一个知识库（类型、文件夹、范围；写入前先给预览），并把知识库说明行写进助手的指令文件。选到已有知识库的文件夹时按原样登记。要再加一个库时再选一次。安装与建库完成后，客户端会重启它启动的 OpenCode，让对话马上用上新技能和说明行（助手正在处理时，等它处理完再重启）；对话接着进行。
   - 备份、回滚、卸载：同 `install.py backup`、`rollback`、`uninstall`（见 docs/manual-setup.zh-CN.md 第 6 节）。
   - 某个库下面的「关系图」：显示库里 Markdown 文件之间的链接，直接在页面上绘制，不从网络加载任何内容（`GET /api/graph`）。实体、汇总文件、文档、保存在库里的原件（原件文件夹）和尚未建页的链接各用一种颜色；客户端启动后新增或更新的文件加一圈高亮，勾选「只看本次新增或更新」时只留下这些文件和与它们相连的文件。滚轮缩放，拖动平移视图或移动单个文件，点击文件列出它链接到的和链接到它的文件。技能检索时跳过的内容这里同样跳过（归档文件夹、下划线开头的文件、快照和带时间戳的旧版），规范文件里的链接是规则示例，也不画。用 Obsidian 打开这个库文件夹，可以看到更完整的关系图和反向链接；页面上显示库路径，并有「复制路径」按钮。分批入库结束的那一行成果后面，也可以直接打开关系图。
   - 移动知识库，或点某个库下面的「移动」：选要移到哪个文件夹里，然后是 `install.py move` 的预览与确认。
3. 每一步输出的文字显示在它的问题上方。问文件夹时有「浏览…」按钮，打开文件夹浏览器：从家目录或已挂载的移动磁盘开始，逐级打开，选定一个文件夹。不推荐任何文件夹：浏览器从家目录打开。答案里已有的文件夹还不存在时（例如在预览里修改文件夹），浏览器从离它最近的已有上级文件夹打开，并把其余部分填为新建的文件夹名，直接选定即回答该文件夹；清空该名称则回答所选文件夹本身。建库预览用选项确认：「写入」「先修改某一项」（再选改哪一项）或「取消」；在终端里运行 `install.py` 时仍是输入同样的回答。
4. 步骤顺利完成后，面板收起为标题和结果一行（点「展开输出」可再看）；取消或出错的步骤保持展开。「安装与建库」补齐首次使用清单缺的项后，清单也自动收起一次；再手动展开就保持展开。
5. 「取消这一步」在当前问题处停止这一步，已完成的部分保留。「退出」停止客户端以及它启动的 OpenCode。关闭页面后，两者也会在一段时间后自动停止（`--idle`），助手仍在处理或有知识库开着自动入库时除外。

### 首次使用清单

页面顶部的卡片列出对话需要的条件，缺哪项就写明怎么补：找到 OpenCode（装好后点「重新检测」，按启动时的方式重新查找）、OpenCode 已启动（停止或退回简易模式后点「重新检测」重新启动；配置里没有模型时在这一项给出提示）、三个知识库技能已装到 OpenCode 能读到的位置（它自己的技能文件夹、`~/.claude/skills` 或 `~/.agents/skills`；其他技能和其他助手不算）、已建好知识库、OpenCode 的指令文件里已写明知识库（它的 `AGENTS.md`；没有这个文件时是 `~/.claude/CLAUDE.md`）。后三项由「安装与建库」补齐。第六项可选，说明是否装了 `pdftotext`。前五项都完成后显示三个示例请求，点一下填进输入框，改好再发送。卡片可以收起，页面在浏览器里记住这个选择。还没有知识库时，对话区上方的任务按钮不可用。顶栏常驻一个标签，同样只看知识库技能（「已安装 3/3」或缺哪几个）；点开列出每个技能的位置、版本和检查过的文件夹，缺的时候有「去安装」。「安装与建库」「卸载」「回滚」完成后，技能列表会重新加载。

### 对话

客户端按下面的顺序查找 OpenCode：`--opencode <路径>`（或环境变量 `KB_CLIENT_OPENCODE`）、程序搜索路径、常见的安装目录（`~/.opencode/bin`、`~/.local/bin`、`~/bin`、`/usr/local/bin`、`~/.npm-global/bin`），最后是交互式 shell（`bash -ic`），这一步也能找到 `~/.bashrc` 里定义成函数或别名的 `opencode`；找到的是函数或别名时，之后都经 `bash -ic` 运行，函数里先做的事（比如刷新配置）照常进行。鼠标停在页面顶部的 OpenCode 标签上，可以看到找到的是什么、怎么找到的。

打开页面时，客户端在后台启动 OpenCode（`opencode serve`，只监听 127.0.0.1，在家目录运行），并显示它启动时输出的内容；启动可能要一段时间，客户端最多等 `--start-timeout` 秒。之后：

- 在底部输入框里提问或提要求；回车发送，Shift+回车换行。助手处理中也可以发送，消息先显示为「排队中」，等当前处理完再处理。「停止」结束助手当前的处理。
- 对话区上方的按钮：「入库」和「随手记」常显，各带一句说明。「继续入库」只在有没做完的入库时出现，「整理随手记」（带条数）只在库的随手记文件夹里有待整理的随手记时出现，「体检」和「归档旧版」收在「更多」里；这几个发出技能自己的说法。有多个库时页面会先问用哪个。
- 「入库」由客户端执行（`intake.py`，本地知识库）：选好库并勾选任意多个文件和文件夹后（隐藏文件和知识库本身不算，最多 2000 个文件），客户端逐个文件运行 kb-incremental 自己的脚本：先 `prep.py scan`（按内容哈希查重、转换、清理），再为每个文件开一个新对话，只请助手做需要判断的部分（在正文文件里修正术语，不做脱敏，正文保持原样；写只含元数据的头文件，把分区、主题、类型、短标题和是否精读写进决定文件）。客户端检查这个答复，不合格时带上原因再问，最多三次；然后运行 `prep.py file`，遇到索引里已有的文件名，交回助手判断是新版本还是换个标题；最后用 `package.py preview --run` 和 `deliver` 写进知识库。只有写入成功的文件才标为「已写入」。对话上方的面板列出每个文件的状态（等待、处理中、已写入及其在库里的文件名、库里已有、需要你处理、失败及原因），结束时给出各项数量和写入位置。「停止」在当前步骤后结束这一轮，「继续」接着做剩下的。重复的按内容哈希跳过，所以再选同样的文件只会补上缺的。读不出文字的文件（扫描件、图片、无法识别的格式）单独列出，并有按钮按原来的方式交给助手处理。入库在单独的「入库」窗口里进行（见下文「窗口」），其他窗口照常可以对话；入库窗口不接受输入，入库进行中也不能关闭。入库进行中，客户端不会因为空闲而自动退出。每一轮入库在所属知识库里自己的文件夹 `<库>/_Runtime/intake/<编号>/` 里进行，每次有变化都把进度存在那里，家目录被还原也不受影响：客户端中途停止（被关闭、被结束或重启）后，下次启动时这一轮显示为「已停止」，并列出还没做的文件，点「继续入库」接着做。已完成的一轮，文件夹保留 7 天后删除。Google Drive 上的知识库仍由助手按原来的方式入库。
- 文件处理完后，同一轮接着整合（面板上的「整合」一步）：知识库的整合队列里还有文件时，客户端开一个新对话，按 kb-incremental 的整合（references/consolidate.md）做一轮，然后重读队列（`consolidate.py list`）再做下一轮，面板上显示第几轮、整合了几个文件、状态卡等改动几条、队列还剩几个。队列清空、队列连续两轮没有变少、或轮数超过队列文件数再加两轮时结束，并说明原因。开着「全部允许」时，从第一个文件到最后一轮都不需要人：每轮按推荐「全部采用」状态卡等汇总文件的改动，运行中助手弹出的选择题按标「推荐」的选项回答（没有就选第一个），都记进 intake.log；采用的改动列在每一轮的说明文件里，旧的汇总文件移到归档文件夹，可以用「回滚」或从归档恢复。没开时，每一轮把改动清单作为选择题弹出，等你回答；等人回答的卡片（选择题或权限）不计入单次答复的时限（每个文件 20 分钟，每轮整合 1 小时）。「停止」和「继续」对整合同样有效。入库进行中，面板上提示这会运行较长时间、页面可以留着不管，期间可以在其他窗口做别的事；入库窗口里没有「在终端打开」，因为它会接到入库正在用的对话上。入库开始时，入库窗口的「全部允许」与点「入库」的那个窗口一致，之后可以在入库窗口里单独开关。
- 自动入库（`auto.py`，本地知识库）：在知识库下打开「自动入库」开关并确认后，库的最上层会建一个投放文件夹 `_待入库`（用英文界面打开时是 `_Inbox`；下划线开头，检索和关系图都会跳过），此后放进去的文件由客户端自动入库，不需要有人看着页面。客户端每分钟查看一次；文件两分钟内不再变化才处理；只要没有写库任务在运行、也没有步骤在进行就开始，其他窗口在对话不影响它（OpenCode 没运行时先启动它）。处理过程与「入库」加随后的整合相同，在入库窗口里进行，期间该窗口打开「全部允许」，结束后恢复关闭；运行中在入库窗口里手动关掉「全部允许」会停止这一轮。每个文件处理完立即移出投放文件夹：已写入且原件已复制到库的 Sources 文件夹，或库里已有的，直接删除；已写入但没有这份副本的（库不保留原件，或文件超过大小上限），移到 `已入库/`（英文为 `Filed/`）；需要人处理或失败的，移到 `未处理/`（英文为 `Not-filed/`），不再重试。被停止的一轮把文件留在原处，并暂停这个库，直到有新文件放进来。没有新文件时，整合队列里还有文件的库会单独跑整合，直到某一轮没能清空队列为止。知识库卡片上显示投放文件夹（带「复制路径」）、等待中的文件数、上次运行（时间、写入、库里已有、需要你处理、整合数和日志位置），并醒目标出 `未处理/` 里有几个文件。只要有知识库开着自动入库，客户端就不会因空闲而退出，一直运行到点「退出」或关机。每个库的开关、投放文件夹（相对于库的位置，库移动后仍然有效）和上次运行记录存在库里的 `<库>/_Runtime/auto-intake.json`。环境变量 `KB_CLIENT_AUTO_POLL` 和 `KB_CLIENT_AUTO_SETTLE`（秒）可以改这两个时间。
- 日志：客户端写入 `~/.config/evergreen-wiki/logs/kb-client-YYYYMMDD.log`（INFO 级别，--log-level 设得更低时按它；保留 7 天，只有本人可读），记录 OpenCode 的启动、重启和停止，每个授权请求和处理结果（只记类型和路径，截断到 200 字符），每一步的开始和结束，以及客户端退出的原因。每一轮入库在自己的文件夹里写 `intake.log`：运行的每个脚本及其参数、退出码和输出的最后几行（扫描卡片里的正文开头和标题不记），给助手的每次提示和用时，每次的决定以及不通过的原因，每个文件写入后的文件名。日志里有文件名和路径，没有文件正文。「管理」区和入库面板显示日志位置，并有「复制路径」。
- 助手提出带选项的问题时，显示为选项卡片；助手用文字要求确认时，在输入框里回复。
- 「新对话」在当前窗口开始一个干净的对话；以前的对话仍保存在 OpenCode 里，可以在那里打开。
- 窗口：对话区上方一排标签，每个标签是一个窗口，各有自己的对话、卡片和「全部允许」开关，都由同一个 OpenCode 处理。「＋」新开一个窗口（最多 8 个，入库窗口不算），「×」关闭窗口，对话仍保存在 OpenCode 里；关闭助手正在处理或有卡片在等的窗口时先确认，确认后先停止再关闭；关掉最后一个窗口时留下一个新窗口。后台窗口的标签上用圆点标出处理中（蓝）或有卡片等你（黄），有新回复时标签加粗。普通窗口用 OpenCode 给对话起的标题，还没有标题时显示「对话 1」「对话 2」；任务窗口显示「体检·库名」等，入库窗口显示「入库」。「停止」「新对话」「在终端打开」「全部允许」只作用于当前窗口。窗口列表和当前标签存在 kb-client.json 里，刷新页面或重启客户端后照原样恢复；入库窗口只在有能继续的入库时恢复。
- 写库任务一次一个：入库、继续入库、自动入库、体检、归档旧版和整理随手记都会改知识库，同一时间只运行一个；「安装与建库」「回滚」「移动」「卸载」也与它们互斥（备份和关系图不受限）。点「体检」「归档旧版」「整理随手记」时，任务在新开的任务窗口里发出，当前对话不受影响。任务窗口里助手处理完、也没有等你回答的卡片时，这个任务就算结束；之后在任务窗口里再发消息（例如回答技能用文字提的确认）会接着这个任务，此时若有别的写库任务在运行，要等它结束。有写库任务在运行时，其他写库按钮置灰，对话区上方提示是哪个任务，并有「查看」切到它的窗口；随手记、提问和其他技能不受限。在普通窗口里直接打字发出的写库请求，客户端认不出是哪个任务，不按这条规则拦；但写库任务运行期间，其他窗口里的助手要改知识库里的文件、运行 kb-incremental 的脚本或执行提到知识库文件夹的命令时，一律弹卡片由你决定，即使那个窗口开着「全部允许」；读知识库、kb-query 的检索脚本和只读命令照常自动放行。简易模式下只有一个窗口，没有标签栏。
- 一个回合结束后，每条回答里的步骤合并成一行（「12 个步骤（读取 5 · 运行命令 6 · 修改文件 1）」，有失败的标红并写明几个），点开可看每一步；回答文字照常显示，子助手的工作同样折叠，重开页面时已完成的回合也是折叠的。对话区高度随窗口变化。
- 助手的处理过程实时显示：每个步骤一行（读取文件、运行脚本等）；思考过程和步骤前的过程说明各折叠成一行灰色小字，点开看全文；正式回复按正常文字显示。交给子助手（OpenCode 自带的助手，如 explore）的工作缩进显示在「子助手」下面，包括子助手自己的步骤、授权请求和提问。
- 入库时，对话区上方显示阶段条：清点、转换、查重与命名、清理正文、比对结论、写入、收尾。当前阶段按正在运行的技能脚本确定（不看助手的措辞），并用一句话说明这一步为什么这样做；点开某个阶段可看详细说明。分批入库时，进度行读取库里的分批进度文件（`GET /api/progress`，只返回数字和分组名）：第几批、共几批、已入库、重复、待复核。每完成一批，对话里多一行成果；整轮结束时再多一行。客户端自动允许的操作合并成一行计数（「已自动允许 N 次」），点开看明细，不再每次一行。
- 分批入库可以跨对话接着做。技能做完一批后因对话变长而停下、且没有别的事在等时，页面倒数三秒后自动开新对话并发出「继续入库」，倒数时可点「取消」。点了「停止」、出错，或者自动续了一轮却一批都没完成时，改为显示「继续入库」按钮。尚未完成的这一轮所选的材料，在每个新对话里读取都不弹卡片（客户端从这一轮的进度文件里取路径）。简易模式下「入库」和「继续入库」不可用，因为助手不能在页面上提问来确认分批计划。
- 思路轮播：欢迎区一次一张卡片，介绍知识库背后的思路（LLM Wiki、常青笔记、名称即版本、状态卡、有证据才改、改写有核对、只归档不删除、规范随材料生长、实体与反链、先快收后整合、先查库再回答），每张一句话，点「详情」再看几句。约 8 秒换一张，鼠标或键盘焦点停在上面时暂停，有上一张、下一张和暂停；系统设了减少动态效果时不自动换。入库时阶段条下方显示一行精简版，点一下换下一张。
- 「技能」一栏在左侧，列出 OpenCode 读得到的全部技能（先是它自己的文件夹，再是 ~/.claude/skills 和 ~/.agents/skills；同名的以前者为准，后者标为未生效），显示版本、描述和触发口令。「试一试」把第一个口令填进对话框，不会自动发送。三个知识库技能排在前面，除「试一试」外只有「升级」：先备份，再用这个客户端带的版本替换 OpenCode 正在用的那份技能文件夹，不问装到哪里、是否替换。已登记的知识库文件夹还在时，知识库不变，只刷新说明行（有变化时问一次）；没有可用的库时，接着问是否建库。已安装的版本相同或更新时，或入库、任务窗口、其他步骤正在写知识库时，按钮置灰，悬停提示说明原因（开着自动入库的，等这一轮结束或先关掉自动入库）。其他技能有「修改」：卡片里选要改的方面（什么时候用、做什么、例子、回答、其他），写一两句说明，并附写好请求的要点；点「备份并准备请求」后，先把技能文件夹复制到 `~/.config/evergreen-wiki/skill-backups/<技能>/<时间>/`，再把请求填进对话框。有备份后出现「回滚」，先备份当前版本，再把选中的备份放回去。「导入」接受含 SKILL.md 的文件夹或 zip：先预览名称、描述、文件和大小，同名、zip 里有指向自身以外的路径或链接、超过 500 个文件或 20 MB 的一律拒绝，绝不覆盖；导入时不运行其中任何内容，复制到 OpenCode 的技能文件夹。「新建技能」问名称和一句用途，写一个待补全的 SKILL.md，并把补全它的请求填进对话框。
- 标题右边的「知识库」按钮用来展开或收起知识库：知识库列表、管理、「技能」一栏、步骤面板、阶段条和首次使用清单里与知识库有关的几项。收起时页面占满窗口，对话左边是只读的技能列表：每个生效的技能一行（名称和描述的第一句；点开看完整描述和触发口令），知识库技能在前，列表在栏内滚动，超过 8 个时出现筛选框。浏览器会记住是否收起；有步骤在运行时自动展开。宽屏上，左栏右上角的「«」把整个左栏收拢成一条窄栏，对话区随之变宽（页面最宽仍为 1440 像素）；窄栏上竖排写着「技能」（知识库展开时为「知识库」），点窄栏任何地方都会展开。浏览器记住是否收拢，用不用 `--chat-first` 分开记住，默认展开；点「知识库」按钮展开知识库时，左栏也一并展开。窄屏上左栏排在对话下面，不提供收拢。页面默认展开，用 `--chat-first` 启动时默认收起。
- 助手的回答按 Markdown 显示：标题、列表、引用、表格、分隔线、行内代码、加粗、斜体和网页链接。代码块用等宽字体，带「复制」按钮，Python、shell、JavaScript、JSON、YAML、SQL 和 diff 有语法着色，其他语言不着色。回答以页面元素构造，从不当作 HTML 插入，其中的内容不会被执行。自己发的消息仍按纯文本显示。
- 「在终端里打开」在新的终端窗口里用 OpenCode 自己的界面打开同一个对话（`opencode --session=<编号>`；终端程序依次尝试 x-terminal-emulator、mate-terminal、gnome-terminal、konsole、xterm），使用用户自己的 OpenCode 设置。在终端里继续时，页面上的这个对话会暂停，回来后刷新页面即可。

授权。客户端启动的这个 OpenCode，所有操作都先设为询问（通过 `OPENCODE_CONFIG_CONTENT`，只作用于这个进程，不改用户的 OpenCode 设置）。以下几类由客户端自动回复「允许这一次」：读写已登记的本地知识库里的文件；读取本次对话选中的材料、已安装的技能和助手自己的设置；派出只负责查找的子助手（explore）；运行已安装技能的脚本（`python3 <技能>/scripts/<名称>.py …`，前面最多一个 `cd <文件夹> &&`，引号内的参数之外不能有其他命令行语法；双引号内含 `$`、反引号或反斜杠时仍需确认）；以及在上述范围内的普通 `mkdir [-p]` 和 `cp [-p|-r|-R]`（cp 可从其中任一处读取，只能写到允许写入的地方），不能带通配符和 `~`；还有只读的命令（ls、cat、head、tail、wc、stat、file、du、grep、rg、不带 -exec、-delete 等动作参数的 find、pwd、echo、test），之间可用 `;`、`&&`、`||`、`|` 连接，最多带 `2>/dev/null`，只用 HOME、USER、KB_LIBRARIES、PWD 这几个变量，且每个路径都在上述范围内。消息里写出完整路径的文件和文件夹，算作本次对话选中的材料（只读）。客户端还在系统临时目录里建一个自己的工作文件夹，退出时删除：任务按钮发出的请求里会写明它（「工作文件夹：…」），技能把副本和输出文件放在这里，写这里和写知识库一样自动放行。子助手的请求按同样的规则处理。每次自动允许都会在对话里记一行。其余操作显示为卡片，写明助手要读、改或运行什么，按钮为「拒绝」和「允许这一次」。OpenCode 给出了以后不再询问的范围时（例如所有 `git` 命令），卡片上列出这个范围，并多一个「总是允许」：客户端把这个回答转给 OpenCode，之后这类操作不再询问，与在终端里一样。客户端也把这个回答记在自己的状态文件（kb-client.json）里，之后同类请求由客户端直接放行，OpenCode 或客户端重新启动后仍然有效；记住的命令范围只适用于单条命令，用 `;`、`|` 等连接的不算。「管理」区显示已记住几项，并有「清除」按钮：清除后客户端忘掉这些回答，并重新启动 OpenCode 让它也忘掉。不改用户的 OpenCode 设置文件。路径按真实路径比较，经符号链接跳出知识库的不放行。

全部允许。对话区标题栏的「全部允许」（每张卡片上也有「本页都允许」）按窗口各自开关：确认一次后，客户端对这个窗口里的请求自动回复「允许这一次」，包括已在等待的卡片，直到再点同一按钮关闭或退出客户端；其他窗口不受影响。写库任务运行期间，其他窗口里写知识库的请求仍弹卡片（见上文「写库任务一次一个」）。刷新页面、「新对话」和分批入库自动续的新对话中都有效；只存在内存里，不写 kb-client.json，也不影响「总是允许」记下的回答。每次自动允许照常计入对话里的计数。对话里的选择题仍等你回答；只有客户端执行的入库会自己回答（见上文「入库」）。简易模式下不可用。

简易模式。OpenCode 的服务没有按时启动，或缺少客户端用到的接口时，对话改为每条消息运行一次 `opencode run <消息>`，并在页面上说明；这种模式下助手不能在页面上请求授权或提问。在「首次使用清单」里点「重新检测」可以再试一次启动服务。

输入的不是绝对路径时，按家目录下的相对路径处理。

选项：`--lang en|zh` 指定语言（默认按系统语言），`--port N` 指定端口（默认自动选空闲端口），`--no-browser` 不打开浏览器、只显示地址，`--idle 秒数`（没有页面打开且没有步骤在运行达到这么久后停止；0 表示不自动停止；默认 120），`--start-timeout 秒数`（等待 OpenCode 启动的时间；默认 90），`--opencode 路径`（指定要用的 OpenCode 程序），`--log-level`。「安装与建库」默认选中工作库；还可用 `--agent <目标>` 和 `--preset life|work` 预先回答这两题，用 `--descriptions <文件>` 替换技能描述，与 `install.py` 相同；可以写一个包装脚本或复制一份 .desktop 入口，为一组使用者固定这些选项。`--simple` 去掉回滚、移动、卸载、「技能」一栏（只读的技能列表保留）和清除已记住授权的按钮，客户端也拒绝这些请求（403）；安装与建库、备份、关系图和对话（包括「全部允许」）照常可用。`--chat-first` 打开时以对话为主，相当于 OpenCode 的浏览器前端：知识库默认收起（见上文「知识库」按钮；浏览器与不带 `--chat-first` 的页面分开记住）。对话上方有工作文件夹、模型列表和「历史会话」。工作文件夹用文件夹浏览器选择（最近 5 个可以直接再选；不能是家目录本身、包含家目录的文件夹或系统文件夹）；OpenCode 在这个文件夹里启动，每个文件夹记住各自的一组窗口（切换文件夹要所有窗口都空闲、没有写库任务在运行），助手在文件夹里读、改文件不再弹卡片；命令（只读命令除外）和文件夹以外的操作仍会询问。模型列表列出 OpenCode 配置里的模型，选择只对当前对话有效，开新对话后恢复默认。「历史会话」按时间倒序列出这个文件夹里的主对话，已在某个窗口打开的标「（已打开）」；点一个就在新窗口里接着聊，已经开着的就切到那个窗口。编辑步骤下有「查看改动」，显示这次编辑的差异（最多 400 行）。客户端不备份助手改动的文件：工作文件夹请选用有版本管理或有备份的文件夹。

## 安全

- 服务只监听 127.0.0.1。打开的地址带一个随机令牌；不带令牌或主机名不对的请求一律拒绝，浏览器里的其他网页无法调用本服务。
- 页面只和本服务通信，由本服务和 OpenCode 通信。OpenCode 自己的服务不设密码，本机任何程序只要找到它的端口就能调用，这与在终端里启动 OpenCode 相同。它只监听 127.0.0.1，端口在启动时随机选定，随客户端一起停止。
- 每个库的运行状态放在库里的 `_Runtime` 文件夹（names.runtime_dir；检索、关系图和体检都跳过它，删掉它只会丢失这些运行状态）。客户端启动时，在任何写库操作之前，先把注册表里每个本地库的 id 和用途写进它的 `_kb.json`（原文件保留为 `_Runtime/kb.json.bak`），这样只看文件夹就知道是哪个库；再把旧版本放在 `~/.config/evergreen-wiki/` 里的自动入库设置和入库进度搬进各自的库。所属的库暂时不在的，留到下次启动再搬。
- 客户端在 `~/.config/evergreen-wiki/kb-client.json` 保存各窗口的对话编号和标题，在 `~/.config/evergreen-wiki/skill-backups/` 保存技能备份。只有「导入」「新建技能」「回滚」在确认后才写技能文件夹，从不写知识库技能的文件夹。
- 同一时间只运行一个步骤。文件夹浏览器只列出文件夹和文件名，且只能浏览家目录和已挂载的移动磁盘之内（其他位置的文件夹仍可直接输入到答案里）；服务只发送页面自己的三个文件；客户端本身不写任何东西，写入的只有安装程序各步骤在确认后写的内容。

## 在桌面上检查

单元测试按页面的方式通过 HTTP 回答问题。改动后请在真实桌面上检查：

1. 双击任一入口（最上层文件夹、tools/kb-client）能打开终端窗口，并在默认浏览器中打开页面。
2. 安装与建库：文件夹浏览器从家目录打开（在预览里修改文件夹时，从当前答案或其最近的已有上级打开，并填好新文件夹名），能看到已挂载的移动磁盘，选定后的路径出现在问题里；确认前能看清预览。
3. 移动：移动后页面上该库显示新位置，重启助手后能在新位置查到库里的内容。
4. 卸载：知识库文件夹默认保留，逐个选定并输入确认词后才删除。
5. 「取消这一步」停止当前步骤且不再改动任何东西；「退出」停止客户端，终端窗口随之关闭。
6. 对话：OpenCode 能启动，页面显示「已就绪」（记下用了多久）；问一个知识库里有的问题，能按库作答。
7. 入库：勾选两个文件夹；请求里列出这两个路径，不再弹出别的选择框，不用终端就能一直做到入库说明。读取材料、写知识库不弹授权卡片；做这两者以外的操作时弹出卡片。
8. 重开页面后还是同样的几个窗口和对话；「新对话」在当前窗口开始一个干净的对话。开两个窗口，一个处理中时另一个能正常对话；体检进行中，「入库」等按钮置灰，入库期间其他窗口能对话。
9. 点「退出」后，没有残留的 `opencode serve` 进程（`ps -ef | grep "opencode serve"`）。
10. OpenCode 只在终端里配置好（写在 `~/.bashrc` 里）时，双击启动也能找到它；页面顶部标签能看到是怎么找到的。
11. 子助手工作时，它的步骤缩进显示；派 explore 时不弹授权卡片。
12. 思考过程和过程说明折叠显示；助手处理中发出的消息显示为排队中。
13. 「在终端里打开」能在终端窗口里打开同一个对话。
14. 「安装与建库」默认选中工作库和 OpenCode；完成后不用重启任何东西，就能直接问新库里的内容；重开客户端后，技能和知识库仍正常列出。
15. 在卡片上选「总是允许」后，同类操作不再弹卡片；记下退出并重开客户端后是否仍记住。
16. 入库 10 个文件：除确认分批计划外，没有关于工作文件夹或 mkdir、cp 的卡片。
17. 分批入库（多于一批）：阶段条随步骤变化，进度行按批计数，每完成一批多一行成果，整轮结束再多一行。
18. 关系图：能从库卡片和入库结束的那一行打开；本次入库的文件带高亮圈；用「复制路径」复制的文件夹能在 Obsidian 里打开。
19. 原件：新建的工作库里，入库的 Word 或 PDF 在 Sources/ 下有一份与主题文件同名的副本；在 Obsidian 里点主题文件头的 original 链接能打开它；关系图里显示为原件；新版入库后旧副本移入归档文件夹。
20. 批次较多的分批入库：技能做完一批停下后，页面自动开新对话接着做，读材料不弹卡片；点「取消」或「停止」后留下「继续入库」按钮。
21. 首次使用清单：在还没有技能和知识库的电脑上，卡片列出缺少的项，用「安装与建库」逐项补齐；装好 OpenCode 后点「重新检测」，不用重启客户端就能开始对话；「安装与建库」的预览用「写入」「先修改某一项」「取消」三个选项确认。
22. 少弹卡片：「安装与建库」完成后步骤面板和首次使用清单自动收起；用 ls、head、grep 查看库或材料里的文件不弹卡片；消息里写的路径读取时不弹卡片；退出并重开客户端后「总是允许」仍然记得，「管理」区的「清除」能让它忘掉；已完成的回合步骤合并为一行。
23. 思路轮播：卡片会自动切换，鼠标停在上面时暂停；桌面设了减少动态效果时，不点「下一张」就不换。浅色和深色主题下字体与颜色都清楚易读。
24. 技能：「试一试」只填对话框不发送；「修改」先备份再填请求；助手改完后「回滚」能恢复原版。kb-query 只有「试一试」和「升级」，刚做完「安装与建库」时「升级」是灰的；版本较旧时，有知识库的情况下「升级」不提任何问题，任务窗口工作时「升级」是灰的；用 ls 列它的文件夹不弹卡片。
